 CV GENERATION - EXTRA DATA COMMANDS (curl)  [companion to cv-generation-commands.txt]

 This file documents the SECOND pass: adding the remaining CV data that the
 first file does not cover, then regenerating the two CVs.

 Extra data added to the SAME beneficiary (Amina Kaci, user id 27):

0. SESSION SETUP  (three actors, three cookie jars)
--------------------------------------------------------------------------------
 The workflow needs three different accounts. All are seeded (see
 prisma/seed_users.ts). Run the API with translation on for the FR step:

   # repo root
   docker compose up -d jadara_db jadara_drive libretranslate

   # backend
   CV_TRANSLATION_ENABLED=true PORT=3000 node dist/src/index.js

 Base URL:  http://localhost:3000/v1

   # beneficiary (user id 27) - the person the CV is for
   curl -s -c /tmp/opencode/ben.cookies   -X POST http://localhost:3000/v1/auth/login \
     -H "Content-Type: application/json" \
     -d '{"email":"amina.kaci@example.com","password":"Passw0rd123"}'

   # organization (user id 6 -> organizations.id 4 "Jadara Volunteers")
   curl -s -c /tmp/opencode/org.cookies   -X POST http://localhost:3000/v1/auth/login \
     -H "Content-Type: application/json" \
     -d '{"email":"organization@jadara.com","password":"Organization@12345"}'

   # admin (user id 1)
   curl -s -c /tmp/opencode/admin.cookies -X POST http://localhost:3000/v1/auth/login \
     -H "Content-Type: application/json" \
     -d '{"email":"admin@jadara.com","password":"Admin@12345"}'

 Responses (real):
   organization@jadara.com -> {"success":true,"data":{"user":{"id":6, "role":"Organization"}}}
   admin@jadara.com        -> {"success":true,"data":{"user":{"id":1, "role":"Admin"}}}

       create -> (submit) -> Admin verifies. Here we create then force-verify.

10. BEHAVIOUR NOTES
================================================================================
 * Projects: only status "verified" projects enter the CV snapshot.
 * Volunteering: the CV reads user_completed_volunteering, which is created
   ONLY by POST /v1/volunteer-applications/{id}/complete (not by accept).
 * complete requires the activity end_date to already be in the past, and the
   application to be in "accepted" state.
 * Activities must be approved by an Admin before beneficiaries can apply.
 * A single POST /users/me/pdf-generate with {"languages":["EN","FR"]} queued
   BOTH jobs at once (25 EN, 26 FR) with cached=false, because the data had
   changed since the previous generation. An unchanged demand would instead
   come back cached=true with the stored download_url.
 * Each language has its own cache/version: after adding new data a fresh
   demand returns cached=false and generates a new uuid, so both PDFs are the
   CURRENT snapshot, not a stale one.
 * IDs used in this run: user 27, org user 6 / organizations.id 4,
   activity 17, application 12, project 6, certification 9, work 7, jobs 25
   (EN) and 26 (FR).
