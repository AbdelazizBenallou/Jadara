================================================================
  REGISTER API — POST /v1/auth/register
  Base URL: http://localhost:3001
================================================================

Register creates a user depending on the role:

  - Beneficiary (role_id=1): JSON body -> active immediately (201) + cookies
  - Reviewer    (role_id=2): multipart files[] + domain_ids -> pending (201), NO cookies
  - Company     (role_id=3): multipart files[] -> pending (201), NO cookies
  - Admin (role_id=4): not allowed (400)

Rate limit: 30 requests per hour per IP (429 after.)


--------------------------------------------------
1. BENEFICIARY — SUCCESSFUL REGISTRATION (201)
--------------------------------------------------
Active immediately, cookies set.

curl -X POST http://localhost:3001/v1/auth/register \
  -H "Content-Type: application/json" \
  -d '{
    "email": "newuser@jadara.com",
    "password": "Secret123",
    "first_name": "Patrik",
    "last_name": "Jadara",
    "phone": "+213558340669",
    "gender": "Male",
    "role_id": 1
  }'

Expected: 201
{
  "success": true,
  "message": "Registration successful",
  "data": {
    "user": {
      "id": 3,
      "email": "newuser@jadara.com",
      "status": "active",
      "profile": {
        "id": 3,
        "user_id": 3,
        "first_name": "Patrik",
        "last_name": "Jadara",
        "phone": "+213558340669",
        "date_of_birth": null,
        "gender": "Male",
        "avatar": null,
        "created_at": "2026-08-28T16:00:00.000Z",
        "updated_at": "2026-08-28T16:00:00.000Z"
      },
      "role": "Beneficiary"
    },
    "demand": null
  }

Cookies set:
  Set-Cookie: accessToken=...; Path=/; HttpOnly; ...
  Set-Cookie: refreshToken=...; Path=/v1/auth; HttpOnly; ...

DB: users (status=active) + profiles + refresh_tokens inserted


--------------------------------------------------
2. REVIEWER — SUCCESSFUL REGISTRATION (201, PENDING)
--------------------------------------------------
Multipart. Requires at least one domain (domain_ids) and at least
one proof document (files). User is created with status=pending and
a registration demand is created. NO cookies are set.

curl -X POST http://localhost:3001/v1/auth/register \
  -F "email=reviewer@jadara.com" \
  -F "password=Secret123" \
  -F "first_name=Review" \
  -F "last_name=Er" \
  -F "role_id=2" \
  -F "domain_ids=1" \
  -F "domain_ids=8" \
  -F "files=@/path/to/cv.pdf"

Expected: 201
{
  "success": true,
  "message": "Registration submitted for review",
  "data": {
    "user": {
      "id": 5,
      "email": "reviewer@jadara.com",
      "status": "pending",
      "profile": {
        "id": 5,
        "user_id": 5,
        "first_name": "Review",
        "last_name": "Er",
        "phone": null,
        "date_of_birth": null,
        "gender": null,
        "avatar": null,
        "created_at": "...",
        "updated_at": "..."
      },
      "role": "Reviewer"
    },
    "demand": { "id": 1 }
  }

NO cookies set (user cannot log in until approved).

DB: users (status=pending) + profiles + demands (pending) +
    demand_domains (1 per requested domain) +
    documents (type=demand, uploaded to MinIO bucket "documents"
    under folder "demands/<userId>/")

domain_ids also works comma-separated: -F "domain_ids=1,8"

--------------------------------------------------
4. VALIDATION ERRORS (Zod -> 422)
--------------------------------------------------
Happens for any role (Base Zod schema).

--- Missing email ---
curl -X POST http://localhost:3001/v1/auth/register \
  -H "Content-Type: application/json" \
  -d '{ "password": "Secret123", "first_name": "P", "last_name": "J", "role_id": 1 }'

Expected: 422 {"success":false,"message":"Validation failed"}

--- Invalid email format ---
curl -X POST http://localhost:3001/v1/auth/register \
  -H "Content-Type: application/json" \
  -d '{
    "email": "notanemail", "password": "Secret123",
    "first_name": "P", "last_name": "J", "role_id": 1
  }'

Expected: 422

--- Password too short (< 8 chars) ---
... "password": "Ab1" ... -> 422

--- Password missing uppercase/lowercase/number ---
"password": "secret123" -> 422 (regex "Must contain uppercase, lowercase, and number")

--- Missing first_name / last_name --- -> 422

--- role_id missing --- -> 422

--- role_id negative --- -F "role_id=-1" -> 422

--- role_id invalid (e.g. 999) ---
Expected: 400 {"success":false,"message":"Invalid role"}

--- Admin role not allowed ---
... "role_id": 4 ...
Expected: 400 {"success":false,"message":"Invalid role"}


--------------------------------------------------
5. EMAIL ALREADY EXISTS (409)
--------------------------------------------------
Email uniqueness is global (users table), checked before role logic.

curl -X POST http://localhost:3001/v1/auth/register \
  -H "Content-Type: application/json" \
  -d '{
    "email": "patrik@jadara.com", "password": "Secret123",
    "first_name": "P", "last_name": "J", "role_id": 1
  }'

Expected: 409 {"success":false,"message":"Email already registered"}

--------------------------------------------------
9. UPLOAD LIMITS
--------------------------------------------------
- Up to 5 files (middleware upload.array("files", 5))
- Allowed MIME types: pdf, images, word, ppt, zip, txt (see
  framework/middleware/upload.ts)
- File size limited by env.UPLOAD_MAX_FILE_SIZE


--------------------------------------------------
10. RATE LIMIT (429)
--------------------------------------------------
-- Send 31+ requests within 1 hour:
for i in $(seq 1 31); do
  curl -s -o /dev/null -w "%{http_code}\n" \
    -X POST http://localhost:3001/v1/auth/register \
    -H "Content-Type: application/json" \
    -d "{
      \"email\": \"user${i}@jadara.com\", \"password\": \"Secret123\",
      \"first_name\": \"User\", \"last_name\": \"${i}\", \"role_id\": 1
    }"
done

Expected: first 30 return 201, 31st returns 429
Response: { "success": false, "message": "Too many requests, please try again later" }


--------------------------------------------------
11. LOGIN WHILE PENDING / NOT ACTIVE (403)
--------------------------------------------------
Pending or rejected users cannot log in:

curl -X POST http://localhost:3001/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{ "email": "reviewer@jadara.com", "password": "Secret123" }'

Expected: 403 {"success":false,"message":"Account is not active"}

Same for any protected route (verifyAccessToken returns 403).

Normal login works only after admin approves the demand (see
doc/demands/approve-demand.txt).


--------------------------------------------------
12. SUMMARY — ROLE BEHAVIOR
--------------------------------------------------
Role           Body type            Status on create  Cookies   Demand row
----------------------------------------------------------------------------
Beneficiary    JSON (application/json)   active       yes       none
Reviewer       multipart files+domains   pending      no        yes
Company        multipart files           pending      no        yes
